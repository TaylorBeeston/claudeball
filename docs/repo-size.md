# Repository size: analysis, lean layout, guardrails, and how to slim the history

Measured on 2026-10-04 (main at `0b4719e`, 343 commits). Everything was prepared and tested in scratch clones under `~/claudeball-slim/`. Nothing here changes the real repository: no history rewrite, no force-push, no branch changes.

The biggest single path is `assets/players/player_base.glb`: 20 versions, 108 MB on disk, the latest 26.4 MB raw. Every full player regeneration committed ~14 plain GLBs (~165 MB raw), 14 optimized GLBs, 14 lod1 files, and sometimes the 1k set too. That is the 100–160 MB of history per regeneration.

**What feeds the deploy** (`vite.config.ts` → `shippedFile`): `assets/field_layout.json`, `assets/players/player_manifest.json`, `assets/optimized/{field,stadium,ball,bat,bat_donut}.glb`, `assets/optimized/players/{player_base,player_ballkid,player_coach,player_umpire,player_umpire_base}.glb` plus `gear_defaults.json` and `textures/*.webp`, `assets/optimized/players_1k/` (the same 5), plus `public/` and the code. The build also reads `assets/shipped.json` and (only for a warning) `assets/derived.json`.

**Build intermediates** (`tools/repo-diet/intermediates.txt`): plain exports `assets/players/*.glb`, `assets/players/lod1/`, `assets/{field,stadium,ball,bat,bat_donut}.glb`; unshipped `assets/optimized/lod1/`, `optimized/lod/`, the 9 role files under `optimized/players/` and `players_1k/`; and the `assets/tex/` dumps. They are recreated by:
- the Blender builds (`assets/src/*.py`, ~13 min for the players, ~1 min for field and stadium);
- `assets/optimize.sh`, `assets/src/perf_all.sh` and `assets/src/ktx_world.sh`;
- `npm run assets:derive`.

`assets/src/mpfb/tex/` (the CC0 MPFB skin and hair photos) is already git-ignored. Asset work needs it, so it belongs in the intermediates archive too (see 2b).

## 2. The lean layout

**(a) Tracked:**
- code, docs, tests, `public/`;
- the Blender source scripts and their small inputs (`assets/src/`: scripts, CC0 PBR sources, `.npz`), which are expensive to recreate;
- exactly the shipped assets listed above, plus the metadata JSONs.

The tree goes from 403 MB to 103 MB (530 files).

**(b) Not tracked** (git-ignored, regenerable): the intermediates.
- They are regenerated by the commands above, or downloaded with `npm run assets:fetch`. That fetches one archive (~285 MB, gz) published as a **GitHub Release asset** and pinned by `assets/intermediates.lock.json` (URL + sha256).
- The archive is made with `npm run assets:pack` + `gh release create`. It is only needed for asset work: `vite build` and CI never fetch it.
- GitHub Release assets have no CORS headers, but they are only downloaded at build or dev time, never by the browser.
- Release assets don't count toward the repository size and have no bandwidth quota. A Hugging Face dataset repo would work too, but it is one more account and token.

**(c) Git LFS: not recommended.**
- The free quota is 1 GB storage and 1 GB/month bandwidth. Every Pages deploy checks out the shipped assets (~70 MB with `lfs: true`), so about 14 pushes a month would exhaust it. After that, deploys fail or need paid data packs.
- It also adds a client dependency for every thread and machine.
- Plain tracked binaries are fine once only the shipped set is tracked: its whole history compresses to ~100 MB, because aggressive repacking deltas the versions against each other.
- `.gitattributes` marks binaries `binary -diff`, so they are never text-diffed or merged.

**(d) CI / deploy:** unchanged. The workflow still runs `npm ci`, typecheck, vitest, the HDRI fetch, the build and the deploy; all its inputs stay tracked. Two additions:
- the checkout gets `fetch-depth: 2`;
- a size-check step runs before `npm ci`.

The layout is applied by `node tools/repo-diet/apply-lean-layout.mjs` (idempotent; review with `git diff` before committing). It does the following:
- extends `.gitignore` with the intermediate paths;
- writes `.gitattributes`;
- `git rm --cached` any intermediates still tracked (the files stay on disk);
- makes the `vite.config.ts` freshness check skip derived-asset sources that are not present;
- makes `assets:derive` say "run `npm run assets:fetch`" when the plain exports are missing;
- adds the npm scripts `assets:fetch`, `assets:pack` and `size:check`;
- adds the CI size step.

## 4. Guardrails

- **CI**: `node tools/repo-diet/check-size.mjs` (also `npm run size:check`) fails the deploy when:
  - a build intermediate is tracked;
  - a single file is over 25 MB;
  - a commit adds over 80 MB of new file data (a full re-export of the shipped players is ~65 MB);
  - the tracked tree is over 160 MB.
- Limits can be raised for one run with `CB_SIZE_MAX_ADD_MB`, `CB_SIZE_MAX_FILE_MB` or `CB_SIZE_MAX_TREE_MB`; say why in the commit message.
- **Pre-commit**: run `git config core.hooksPath tools/repo-diet/hooks` once per clone. The hook runs the same check on the staged changes.
- **Rules for contributors and threads:**
  - Never commit plain Blender exports, lod1, role files or texture dumps; they are ignored anyway.
  - Commit only the shipped outputs of `assets/optimize.sh` (players via `src/perf_all.sh`, the world via `src/ktx_world.sh`) and `npm run assets:derive`.
  - Batch asset regenerations: one commit per finished pass, not one per experiment. Every re-commit of the shipped player set adds ~40–65 MB raw (much less once packed).
  - To rebuild assets, first run `npm run assets:fetch` (or the Blender builds). Then run `assets/optimize.sh` and `npm run assets:derive`.
  - After a pass that changes the plain exports, the maintainer re-publishes them: `npm run assets:pack`, `gh release create assets-YYYY-MM-DD dist-intermediates/*.tar.gz`, then commit `assets/intermediates.lock.json`.

## 5. How to do it (only when all threads are merged and quiet)

Common preparation, on the machine holding the real repository (`~/dev/test/ai/claudeball`):

```sh
cd ~/dev/test/ai/claudeball
git status && git worktree list          # everything merged? note the worktrees; nothing uncommitted
git fetch origin && git log -1 origin/main && git log -1 main   # main == origin/main
git bundle create ~/claudeball-backup.bundle --all             # full backup of every branch (keep it)
git bundle verify ~/claudeball-backup.bundle
```

### Option A: same repository, rewritten history (recommended)

```sh
# 1. a fresh copy of main to rewrite (never filter the working repository itself)
git clone --no-local --single-branch --branch main ~/dev/test/ai/claudeball ~/claudeball-rewrite
cd ~/claudeball-rewrite
uvx git-filter-repo --invert-paths --paths-from-file tools/repo-diet/intermediates.txt
node tools/repo-diet/apply-lean-layout.mjs && git add -A && git commit -m "repo: lean layout (docs/repo-size.md)"
git reflog expire --expire=now --all && git gc --aggressive --prune=now && git count-objects -vH   # ~102 MB

# 2. verify: same checks as CI, and the same deploy output as today
npm ci && npm run typecheck && npx vitest run && CB_BASE=/claudeball/ npm run build && npx tsx tools/perf/sanity.ts --prod --no-build
(cd dist && find . -type f ! -name asset_sizes.json -print0 | sort -z | xargs -0 sha256sum) > /tmp/new.sha256
(cd ~/dev/test/ai/claudeball && CB_BASE=/claudeball/ npx vite build && cd dist && find . -type f ! -name asset_sizes.json -print0 | sort -z | xargs -0 sha256sum) > /tmp/old.sha256
diff /tmp/old.sha256 /tmp/new.sha256 && echo identical

# 3. publish the intermediates (from now on they exist only in the old checkout): plain exports, lod1, role files, texture dumps, MPFB photos
npm run assets:pack -- --from ~/dev/test/ai/claudeball     # -> dist-intermediates/*.tar.gz (~285 MB) + assets/intermediates.lock.json
gh release create assets-$(date +%F) dist-intermediates/*.tar.gz --title "assets-$(date +%F)" --notes "build intermediates (docs/repo-size.md)"
git add assets/intermediates.lock.json && git commit -m "assets: intermediates archive lock"

# 4. replace main on GitHub (only after you confirm; the lease protects against pushes you have not seen)
git remote add origin git@github.com:TaylorBeeston/claudeball.git
git push --force-with-lease=main:$(git -C ~/dev/test/ai/claudeball rev-parse origin/main) origin main
```

After A:
- GitHub Pages and the Actions settings stay as they are, and the deploy runs on the push.
- GitHub shrinks the stored size after its own garbage collection (hours to days). For an immediate reclaim, ask GitHub Support to run a GC.
- Every existing clone, worktree and thread branch now has unrelated history. Re-clone `~/dev/test/ai/claudeball`:
  1. `git worktree remove` each thread worktree.
  2. Move the old checkout aside.
  3. `git clone git@github.com:TaylorBeeston/claudeball.git`.
  4. Copy back the ignored local files: `public/hdri/`, `assets/src/mpfb/tex/` (or `npm run assets:fetch`).
  5. Run `git config core.hooksPath tools/repo-diet/hooks`.
  6. Let the coordinator re-create the thread worktrees from the new main.
- Old commit hashes in docs and reports no longer resolve; the backup bundle keeps them.


## 6. Recommendation

**Option A, once every thread is merged and quiet.**
- It takes the repository from 742 MB to 102 MB while keeping all 343 commits with their messages and authorship.
- Pages and Actions stay as they are, and the deploy output is byte-identical.
- B only saves another ~50 MB, at the cost of the history and a repository swap.
- Do not adopt Git LFS (deploy checkouts would burn the 1 GB/month free bandwidth).

The lean layout and guardrails can be merged now, before any rewrite. They stop the growth today, but the CI step will fail until the intermediates are untracked. So, to merge the tooling without the rewrite:
1. run `apply-lean-layout.mjs` on main;
2. commit the untracking (the intermediates stay in the old history until A or B removes them);
3. publish the intermediates archive.
